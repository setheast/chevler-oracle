## Rulings

1. **A die fits the machines it has run on, never a group tag** (Seth, 13 Nov 2026; settles the data side of R25).
   - Access tags 64 single-head dies to a machine group: 49 "1-5REEL" and 15 "6-7REEL". The sandbox had read that as "fits every machine in the group", so it offered and "proved" routes on machines a die had never been on.
   - **The booking rule:** each group die is booked to every machine of its group that has **orders** for its size in the Access history (shop orders from 8 Dec 2010).
     - Size matching is the proven rule's own: either way round, D3 when set.
     - Products set up but never ordered don't count.
   - **Result:** 52 dies to one machine, 6 to two, 6 with no orders.
   - **Safety net (test):** no machine that has run a size with orders loses that size's die. The proven machine always keeps its die.
   - **Caveat:** Access holds one route per product, so "ran on" = the machine the product is set up on. Oracle's work orders will record the actual machine per job and should refine this.
2. **More than one machine = one question.** The six dies whose size has orders on two machines are booked to both:
   - 40×26: 5REEL + 3REEL (the 3REEL orders are 2015 only)
   - 41×25, 44×32, 45×25: 4REEL + 5REEL
   - 51×32: 4REEL + 3REEL
   - 51×38: 1REEL + 2REEL

   Julian Collis is asked whether each is two physical dies or one that moves. Oracle's tool record should be able to hold either: separate dies per machine, or one die with several fitting machines and a move cost.
3. **No orders = reference, not deleted.** 38×23, 50×28, 50×38, 64×44×40, 65×15 and 152×86×63 have no orders on their group since Dec 2010.
   - They are listed, but never fitted or routed, until Stuart / Julian say which machine.
   - Oracle should seed them with a low data-confidence level and no fitting machines.
4. **Tool identity:** sandbox jobs reference a die by its NAME (`toolName`; there is no id), so names were kept and the tag moved into notes. **Oracle should reference tools by id** and keep the Access name as a label.

## What changed in the sandbox
- `server/die-bookings.ts` + tests.
- `sameSize` is exported from `route-optimiser.ts`.
- New admin route `POST /api/cases-params/book-group-dies` (dry-run preview, then one audited, rollbackable edit).
- Settings → Tools button "Book group dies to their machines".

No engine change, so no price moves on saved work. Fresh jobs are no longer offered a group die on machines it never ran on. For example, 45×25 is now on 4REEL / 5REEL only.
